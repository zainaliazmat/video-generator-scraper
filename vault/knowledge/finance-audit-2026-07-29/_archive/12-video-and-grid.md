## A1 · Does HyperFrames render `<video>` deterministically? — **YES**

**FACT.** It does not play the video in real time and screenshot it. The renderer
**pre-extracts the clip to a frame sequence with FFmpeg and injects the correct
frame as an `<img>` before each capture.** Determinism is by construction — the
`<video>` element's own `currentTime` is irrelevant during render.

### Citations

**1. The skill says so.**
`~/.claude/skills/hyperframes-core/references/variables-and-media.md:109`

> Input codecs: render decodes video via FFmpeg (**frames are pre-extracted and
> injected**), so HEVC/H.265 assets (8/10-bit) render correctly everywhere; live
> preview auto-proxies any browser-hostile asset…

**2. The injector exists in the local package.**
`studio/packages/engine/src/services/videoFrameInjector.ts:1-8`

```
/**
 * Video Frame Injector
 *
 * Creates a BeforeCaptureHook that replaces native <video> elements with
 * pre-extracted frame images during rendering. This is the Hyperframes-specific
 * video handling strategy …
 */
```

It imports `FrameLookupTable` from `./videoFrameExtractor.js` (the ffmpeg exploder)
and `injectVideoFramesBatch` from `./screenshotService.js`.

**3. The runtime knows it is in injected mode and stops seeking.**
`studio/packages/core/src/runtime/media.ts:293-305`

```
// Skip the per-tick seek (and the `el.load()` drift-recovery retry
// below) for `<video>` elements that have a sibling
// `<img id="__render_frame_<id>__">`. The sibling is created only
// by the producer's frame-injection pipeline during render — its
// presence means the visual is painted from the `<img>` and the
// `<video>` is `visibility: hidden`. Audio is mixed by ffmpeg from
// source files in `runAudioStage`, never via Chrome's in-browser
// audio path.
```

**4. The injection itself.** `studio/packages/engine/src/services/screenshotService.ts:481-556`
creates `<img class="__render_frame__" id="__render_frame_<videoId>__">` as a
sibling, copies the video's computed visual styles onto it, sets `img.decoding =
"sync"`, `await img.decode()`, then `video.style.setProperty("visibility",
"hidden", "important")`. Frame N is fully decoded before the screenshot.

**5. The earlier agent's `init.ts` finding was a red herring.** `init.ts` writing
only `style.visibility` on `.clip` elements is the *clip gate*. Media playback is
a separate subsystem (`runtime/media.ts` + `engine/services/videoFrame*`), and
during render it is a *producer* hook, not runtime code at all.

**6. We have already shipped it in this repo.**
`compositions/video-02-claude-edits-video/index.html:123-130` — eight root
`<video>` clips in a delivered composition:

```html
<video id="b01v0-vid" class="clip vid-artifact" src="assets/excerpts/ex-1907.mp4"
       muted data-start="0.5" data-duration="8.25" data-track-index="6"></video>
```

Generated by `compositions/video-02-claude-edits-video/build.mjs:3` —
*"Contract-safe: `<video>` clips are DIRECT children of root (the framework owns
playback)"*. `vault/skills/hyperframes_production.md:39-42` already documents the
rule set from that build.

### Exact markup required

```html
<div id="root" data-composition-id="main" data-width="1920" data-height="1080" …>
  <!-- DIRECT child of #root. Never inside <section class="scene">. -->
  <video id="s1bg" class="clip bg" src="assets/video/s1.mp4"
         muted playsinline
         data-start="0" data-duration="18.771" data-track-index="5"></video>
  <section id="s1" class="scene clip" data-start="0" …>…</section>
</div>
```

Required attributes and rules (**FACT**, `variables-and-media.md:65-107`,
`data-attributes.md:23-35`):

| Rule | Source |
|---|---|
| **Direct child of the host root** — not inside a `<section>`, not inside any wrapper `<div>`, not inside a sub-comp `<template>`. Violation → renders **black**, and `lint`/`check` do **not** catch it. | `variables-and-media.md:65` |
| `muted` + `playsinline` mandatory | `variables-and-media.md:72` |
| Audio (if any) is a **separate `<audio>`** element, even from the same file | `variables-and-media.md:104` |
| `class="clip"` is **optional** on `<video>` — the framework manages its visibility directly | `data-attributes.md:23` |
| `data-duration` may be omitted to use intrinsic length; `data-media-start` offsets into the source | `data-attributes.md:31-33` |
| Unique `id` across the assembled page. Duplicate `<video>` ids render **blank** (producer injects by `getElementById`) | `SKILL.md:64` |
| Never call `.play()`/`.pause()`/set `currentTime` in composition code | `variables-and-media.md:98` |
| A sub-comp timeline **cannot** animate a host `<video>` — drive it from the MAIN timeline at global time | `variables-and-media.md:70` |

## A3 · Sourcing — adding `--video` to `tools/stock/pixabay_fetch.py`

### What actually has to change

The existing flow is provider-agnostic already. `provider_hits()` (line 157)
dispatches through `HITS = {"pixabay": …, "pexels": …}` and everything downstream
— `download`, `write_credit`, `build_sheet`, `cmd_candidates`, `cmd_pick`,
`.src` sidecars, the `#N` offset, `@pexels` routing, md5 dedup — operates on the
normalized hit dict `{dl, preview, page, author, license, w, h}`. **Video hits fit
that dict unchanged**, because both video APIs return a poster image URL that
slots straight into `preview`.

Concretely (**ESTIMATE** on line count, **FACT** on the code structure):

1. **Two new hit functions, ~25 lines each** — `pixabay_video_hits()` hitting
   `https://pixabay.com/api/videos/` (same `PIXABAY_API_KEY`; response `hits[].videos.{large,medium,small,tiny}.{url,width,height,size}`,
   plus `duration` and a poster derivable from `picture_id`), and
   `pexels_video_hits()` hitting `https://api.pexels.com/videos/search` (same
   `PEXELS_API_KEY`; response `videos[].video_files[].{link,quality,width,height}`,
   `videos[].image` = poster, `videos[].video_pictures[]` = **~15 evenly-spaced
   poster frames**, plus `duration`).
2. **A second dispatch dict**, `VIDEO_HITS`, selected by the manifest slot's
   extension. `{"s1.mp4": "indian market crowd"}` needs **no new flag** —
   `parse_picks` (line 330) currently force-appends `.jpg`; make it keep an
   explicit extension instead. This is the laziest switch and it composes with
   `@pexels` / `#N` for free.
3. **`_make_cell` and `build_sheet` are unchanged.** They take an image path;
   the poster URL is a jpg. A video contact sheet is the same 3-wide numbered
   grid. Pexels' `video_pictures[]` additionally allows a *motion* sheet — 3
   posters from one clip tiled — if the agent needs to see whether the camera
   moves. Not needed for v1.
4. **Two extra normalized fields**, `duration` and `bytes`, carried into
   `_cand/<slot>.json`. `duration` is load-bearing (see A4 rule 5) — the agent
   must be able to reject a clip shorter than its scene from the sheet metadata,
   without downloading.
5. **`FIN_FAKE_APIS`** — `fake_flat` needs a video sibling:
   `ffmpeg -f lavfi -i color=c=#<hash>:s=1920x1080:d=8 -pix_fmt yuv420p out.mp4`.
   ~5 lines. Required or `--dry-run` rehearsals break.
6. **`pipeline_check.py:251`** — `os.path.getsize(path) < 10240` → *"under 10KB,
   not a usable photo"*. Fine for mp4 too (any real clip clears it), but the
   message lies. One-line fix.

Everything else — CREDITS.txt appending, the `.src` skip-on-unchanged-query
guard, the missing-slot `sys.exit` — works untouched.

### Licence position for monetised YouTube

**FACT** (published licence text; not re-verified over the network this session —
we were told not to call APIs):

- **Pixabay Content License** — free for commercial use including monetised
  video, no attribution required, no permission needed. Prohibits: reselling /
  redistributing the asset essentially unaltered, using identifiable persons in a
  way that is defamatory or implies endorsement, and using content on a
  "competing" stock platform.
- **Pexels License** — free for commercial use including monetised video,
  attribution appreciated but not required. Same three prohibitions in substance.

**Both are clean for a monetised YouTube channel, video as well as stills.** We
already exceed what either requires by writing `CREDITS.txt` per asset
(`write_credit`, line 175) — keep doing that; it is the cheapest possible audit
trail and `pipeline_check.py:253` already enforces it.

One thing that changes with video: **identifiable people are much more prominent
in footage than in stills**, and finance content is exactly the genre where
"person + money problem" reads as a claim about that person. The existing rule
against putting a private individual on screen in a critical context (already
written for `social-quote` in `tools/format.json:80`) should extend to footage.

### India-market pool for video — **thinner than the stills pool. ESTIMATE.**

The stills measurement is real: `vault/knowledge/finance-audit-2026-07-29/05-visuals.md:68`
— *"India-people queries: **~20% first-try usable**. Pixabay's India library is
[thin]"* — and the consequence is documented at :110-112, *"the India cut of an
India-market finance video contains no Indian imagery"*, with :95 recording
**zero India signifiers in 13 slots** for credit-history hi.

No measurement exists for video and none can be made without calling the APIs.
But the prior is bad: on both providers the video library is roughly an order of
magnitude smaller than the photo library, and stock video skews harder toward
generic b-roll (drone cityscapes, slow-motion coffee, laptop hands) than stills
do. **ESTIMATE: expect the India-specific video hit rate to be well under the
20% measured for stills.** The honest v1 posture is therefore:

> Video is an *occasional upgrade* on scenes where a good clip genuinely exists —
> not a replacement for the stills pipeline. A run that finds two usable clips
> across nine scenes has succeeded.

This also happens to sidestep the disk and encode cost (A4 rule 8). If a future
run wants footage on every scene, measure the India video pool first, the same
way 05-visuals.md measured the stills pool.

## A4 · The interaction rules `fin-build` would need

### 1. Placement — the one that will silently ship a black video

**FACT.** Our scenes nest the background two levels below the root:
`vault/videos/good-debt-vs-bad-debt/src/en/index.html:166-167`

```html
<section id="s1" class="scene clip" data-start="0" …>
  <div class="bg" style="background-image: url(assets/img/s1.jpg)"></div>
```

Dropping a `<video class="bg">` in that slot **renders black** — it is not a
direct root child. The video must be **hoisted to `#root`** as a sibling of the
`<section>`, exactly as `build.mjs:3` and `:223` already do for video-02.
`lint` and `check` do **not** catch this (`variables-and-media.md:65`: *"Do not
rely on `lint` or `check` alone; a per-frame `snapshot` reveals the blank panel"*).

### 2. The scene paints over the hoisted video

**FACT.** `tools/scaffold/assets/css/blockframe.css` gives `.scene` a
`background: var(--bg)` (opaque `#0d1017`), and root videos sit *below* scene
chrome in DOM order. `vault/skills/hyperframes_production.md:40` already records
the cost of learning this the hard way:

> Draft-4's white filled mat rendered every screen recording as a blank white
> panel. Never give scene chrome a background that covers the video.

**Rule:** a scene backed by video must carry a modifier (e.g. `.scene.vidbg
{ background: transparent }`) and omit its `.bg` div. This is a `tools/scaffold/`
edit, not something a build improvises (`fin-build.md:35-50`).

### 3. The grade — **works, unchanged. FACT.**

`filter` is in `MEDIA_VISUAL_STYLE_PROPERTIES`
(`studio/packages/core/src/inline-scripts/parityContract.ts:1-26`), which
`injectVideoFramesBatch` copies from the `<video>`'s computed style onto the
injected `<img>` (`screenshotService.ts:491-510`). So
`filter: grayscale(.32) brightness(.62) contrast(1.05)` renders identically on
footage and stills. `transform`, `clip-path`, `mask`, `mix-blend-mode`,
`border-radius`, `object-fit` and `opacity` are copied too.

One CSS delta: `.bg` styles a `background-image`; a `<video>` needs
`object-fit: cover`. One extra rule: `video.bg { object-fit: cover; }`.

### 4. `ken` vs real camera motion

`ken` (`tools/scaffold/assets/js/motion.js:118`) is a slow scale/translate. It
survives injection (`transform` is copied), so it *technically* works on video —
which is the trap. Two motions from different sources fight.

**Rule: a `<video>` background never gets `ken`.** One motion source per frame.
Corollary: the reason to reach for a clip is that it already moves; if it needs
`ken` to feel alive, it should have been a still. This also keeps the
`max_static_hold_seconds: 2.0` intent intact without new machinery.

Also **FACT** (`variables-and-media.md:70`): any per-scene motion on host media
must be authored on the MAIN timeline at *global* time. Our compositions already
use one root timeline with an `S` map, so this costs nothing — but it means the
video's tween lives next to `sceneTransitions`, not inside the scene block.

### 5. Clip length vs scene length — **the sharp edge**

HyperFrames does **not** loop. Seeking past the source end holds the last frame —
a freeze that reads as a render bug.

Our scene durations run **11–28s** (`good-debt-vs-bad-debt` sections: 11.249,
17.099, 17.361, 18.771, 20.051, 23.081, 25.642, 27.967). Stock clips are commonly
**8–20s**. So a straight drop-in will freeze on a majority of scenes.

**Rules:**
- Reject any candidate whose `duration` < `scene_duration + transition_seconds`
  (0.45) — enforceable off the sheet metadata from A3 step 4, before downloading.
- When a clip is otherwise perfect but short, **pre-loop it locally at fetch
  time**: `ffmpeg -stream_loop N -i in.mp4 -t <needed> -c copy out.mp4`. One-time,
  deterministic, keeps the composition simple. Prefer a ping-pong loop
  (`reverse` + concat) for clips with a clear directional move, or the seam reads.
- Never trim by shortening the scene — timing is generated from `timing.json` and
  four copies must agree (`fin-build.md`, and `pipeline_check` asserts it).

### 6. Track indices

**FACT.** `pipeline_check.py:305-313` requires every `<section>` to carry
`data-track-index` and asserts adjacent scenes alternate (1/2), because they
overlap by `transition_seconds` and `hyperframes check` fails
`overlapping_clips_same_track`. That regex matches `<section ...>` only, so root
`<video>` rows will not break it — but `hyperframes check` still will if two
cross-dissolving videos share a lane.

**Rule:** root videos alternate **5/6** down the video, mirroring their scene's
1/2 alternation. This is exactly what video-02 does
(`hyperframes_production.md:39`: *"alternates them across tracks 5/6 so
crossfading neighbours don't collide on one track"*), and index.html:123-130
confirms the shipped pattern.

### 7. Determinism

Unchanged and already satisfied: the clip is a local file under
`assets/video/`. Never a CDN `src` — a render-time fetch is exactly the failure
the vendored-GSAP comment in our own `index.html:5-7` warns about. No
`Date.now()`, no unseeded random. Nothing about video weakens this.

### 8. Disk and encode — **the budget is wrong today**

**FACT:** `videoFrameExtractor.ts:273,454` extracts to **jpg** unless the codec
may carry alpha (h264 stock footage → jpg, not png).

**ESTIMATE:** a 1080p jpg frame at the default quality is ~200–400 KB. A 20s clip
at 30fps = 600 frames ≈ **120–240 MB** of extracted frames. Nine video scenes ≈
**1–2 GB per cut**, ~2–4 GB per hi/en pair, on top of the render itself. Plus the
source mp4s in the project dir (Pixabay `large` ≈ 20–60 MB, Pexels HD similar) —
another ~200–500 MB per cut, which is now inside `vault/videos/<slug>/src/` after
`tools/archive_cut.py`, i.e. **inside git**.

Two consequences:

- `tools/format.json` `tiers.short.disk_gb_per_pair: 1.0` is checked by
  `pipeline_check.py:455-458` (`need_gb = 2 × disk_gb_per_pair`). With video it
  is off by roughly 4×, so `doctor` would pass and the render would fill the
  disk. Raise it, or key it off whether the run uses video.
- Committing 200–500 MB of mp4 per cut to the vault is a real decision, not a
  side effect. Options: `.gitignore` the mp4s and keep only the `.src` query +
  CREDITS line (re-fetchable, and the `.src` sidecar already exists for exactly
  this), or git-lfs. **The `.src`-only option is free and already built.**
- Encode wall clock: extraction is roughly realtime-ish per clip, so ~9 clips ≈
  **+3–8 min per cut** on top of the current ≈36 min of ffmpeg. Not a blocker.

```
reddit-post     block   Animated Reddit post card overlay with upvotes and comments  [social, overlay, reddit]
```

Sources are vendored locally: `studio/registry/blocks/x-post/{x-post.html,registry-item.json}`
and `studio/registry/blocks/reddit-post/{…}`. Both are `type: hyperframes:block`,
1920×1080, `duration: 5`, installing to `compositions/<name>.html`.

### Install path

```
hyperframes add x-post [--dir <project>] [--json]
```

(`add --help`, v0.7.66: *"Install a block or component from the registry into this
project… Single items install directly."* `--json` prints the written files and
the include snippet — the machine-readable form a `fin-build` step wants.)

### What it takes to actually use one

A block is a **sub-composition**, not a snippet. Cost:

1. `hyperframes add x-post` writes `compositions/x-post.html`. Our finance
   compositions are currently a **single flat `index.html`** with no
   `compositions/` dir and no sub-comp hosts — this would be the first one.
2. Wire a host slot in `index.html` with `data-composition-src` + `data-start` /
   `data-duration`, and give it per-instance content via `data-variable-values`.
3. **Restyle it.** The block ships X/Reddit's own visual language (their card
   chrome, their blue). Dropped in raw it will read as a foreign object against
   `blockframe-9`'s grade and type ladder. Budget a `.v-`-prefixed override block
   per `fin-build.md`'s one-off-component rule.
4. **Sub-comp gotchas that apply immediately** (`SKILL.md:63-64`,
   `sub-compositions.md:136`): ids must be prefixed with the composition id or
   the assembled page has duplicates; a sub-comp timeline cannot touch host
   elements; and a slot mismatch makes the render wait 45s per scene then capture
   static initial-state frames — a full-length video with no animation. That last
   one is a genuinely expensive failure mode to hit for the first time on a real
   run.
5. **The photo rule still applies.** `format.json:74` — every frame carries a
   photograph. A social-quote scene is a card *over* a graded photo, not a card
   on flat colour.
